# Core Runtime — Tasks

状态：待需求澄清，未开始实现。

当前没有获准实施的功能任务。需求明确后，按 Feature 新增通常 5～15 个有序 Task；不要将本模板视为实现计划。

## 每个 Task 的记录格式

- 状态：未开始 / 进行中 / 完成 / 阻塞。
- 目标：一个清晰、可验证的增量。
- 影响文件：需求与设计明确后填写。
- 依赖 Task：填写编号或无。
- 新增 / 修改内容：填写具体工作范围。
- 参考位置：已有文件、类或函数；没有则注明无。
- 验证方式与结果：记录执行内容和证据。

## 每个 Feature 的最后两项

1. 接入主流程：明确接入位置、调用路径与可观察行为。
2. 端到端验证：覆盖真实入口到预期输出，记录结果与限制。

具体任务、文件与验证命令待澄清后填写。
